02 / Una trayectoria conectada

El recorrido hasta diciembre de 2027

Cómo usar cada sesión técnica

Empieza recuperando de memoria lo anterior; estudia o implementa una parte pequeña; termina con una comprobación y una nota. En la sesión larga construye y provoca un fallo. El domingo conserva evidencia y repasa los puentes académicos indicados.

Los idiomas permanecen durante todo el plan. Tras el primer recorrido de alemán, consolida contenidos A1 y practica comprensión e interacción con las fuentes externas. Avanzar a A2 debe depender de evidencia y revisión, no del mes del calendario.

Moverte y ganar fuerza con constancia

Desde el 1 de enero de 2027. Las sesiones aparecen en tu checklist diaria y semanal junto al estudio, con minutos separados. Sin horas asignadas: el calendario las exporta como eventos de día completo, sin alarma.

Base semanal: 120 min de natación, 80 min de fuerza y 60 min de caminata. Aumenta gradualmente si vienes de hacer menos. La modalidad mínima de estudio no reduce automáticamente el ejercicio: adapta las sesiones a tu recuperación y usa «Omitir» si hace falta.

Clase o kettlebell de 8 y 12 kg

Elige una opción por sesión. En casa: sentadilla, peso muerto, remo, flexiones adaptadas o press y caminata con pesa; comienza con 2 series, progresa a 3 y deja unas dos repeticiones posibles. Usa 8–12 repeticiones para los movimientos y 30–45 segundos por lado para la caminata con pesa. Descansa 60–120 segundos. Elige la carga que permita buena técnica; aumenta gradualmente repeticiones, carga o dificultad.

03 / Guardar sin pagar una base de datos

Tu avance: navegador y GitHub

1. Avance local y copia en el repositorio

Las casillas, notas, minutos y evidencias se guardan aquí. No se envían automáticamente a GitHub. Exporta el JSON y conserva una copia. Para versionarlo, abre el archivo progress.json en GitHub, reemplaza su contenido por la exportación y guarda el cambio.

Abrir progress.json para guardarlo en GitHub ↗

El repositorio es público: comparte solo datos de progreso que quieras hacer públicos. No guardes información confidencial del trabajo. La web nunca pide un token de GitHub.

2. Checklists de GitHub Issues

El workflow crea una checklist por semana. Si marcas allí una tarea, queda guardada en GitHub y podrás leer ese estado desde otro dispositivo. Los minutos y notas detalladas requieren guardar el JSON.

05 / Todo el mecanismo en GitHub

Recordatorios gratuitos con Actions

El workflow se ejecuta desde la rama principal y usa GitHub Issues para la checklist y los avisos. No necesita un servidor propio, SMTP ni secretos personales. En tu repositorio público utiliza un runner estándar gratuito; si cambias a privado debes revisar sus cuotas.

GuatemalaQué hace

Activación y comprobación
  1. La incorporación a main habilita el workflow si Actions está permitido en el repositorio. Mientras el cambio esté en un pull request, el cron no funciona.
  2. En GitHub → Actions, abre “Atlas · recordatorios de aprendizaje”. Ejecuta “Run workflow” con preview para revisar, o send para crear la checklist del día.
  3. En tus notificaciones de GitHub, activa los canales que quieras para asignaciones, participación y menciones. El email o aviso móvil depende de esa configuración; el sitio no lo garantiza.
  4. Marca una sesión en el issue y pulsa “Cargar tracking de Issues” aquí para comprobar el recorrido completo.

Los avisos dejan de generarse después del 31 de diciembre de 2027. El cron puede seguir haciendo ejecuciones sin envío: puedes deshabilitar el workflow al cerrar el plan. Para pausar antes, cambia enabled a false en tracking/reminders.json o deshabilita el workflow.

GitHub puede retrasar o descartar ejecuciones programadas y deshabilitar el cron de un repositorio público tras 60 días sin actividad. El calendario importado es una alternativa útil si necesitas alarmas a hora fija. El envío real y la entrega a tu correo deben comprobarse después de la activación.
